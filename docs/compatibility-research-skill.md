# Навык проверки совместимости серверной сборки

Применяй этот навык для произвольных пользовательских ведомостей. Историю диалогов используй как обратную связь по процессу; не считай её доказательством технического факта.

## Разбор ведомости

- В ведомости количество — отдельное число сразу после описания позиции. Следующую за ним цену игнорируй: она не является ни количеством, ни характеристикой совместимости. Числа внутри описания считай характеристиками, а не количеством.
- Передавай анализу исходную позицию, название и описание целиком. Не объединяй одинаковые артикулы из разных строк; показывай отдельный вывод для каждой строки.
- Не определяй платформу как накопитель по упоминанию NVMe или M.2 в её описании: это могут быть поддерживаемые интерфейсы. Учитывай тип изделия, модель и точный артикул; обнаруженное расхождение проверяй по источникам.
- RAID/HBA-контроллер не является накопителем, даже если его описание содержит SAS, SATA или NVMe. Тип оборудования определяй по основному изделию, а не по перечисленным поддерживаемым интерфейсам.
- Проверяй все количества совместной установки: число CPU, DIMM, накопителей, карт, слотов, разъёмов и отсеков. Не путай встроенные в платформу слоты/БП с заказанными позициями.
- Если в списке несколько полноразмерных серверов или платформ, не предполагай, что один сервер устанавливается внутрь другого. Считай их отдельными базовыми системами и запрашивай распределение компонентов, если оно не указано. Не приписывай документацию одной платформы другой только из-за совместного поискового запроса.
- Для нескольких CPU в одной системе проверяй не только число сокетов, но и поддерживаемую производителем каждого точного процессора масштабируемость 1S/2S. Процессор 1S не подходит для двухпроцессорной конфигурации даже при совпадении сокета; при неопределённом распределении между платформами запрашивай уточнение. Пример документа Intel: https://www.intel.com/content/www/us/en/support/articles/000089741/processors/intel-xeon-processors.html.
- Если количество не указано или распределение между несколькими платформами неизвестно, явно назови этот пробел; не подставляй единицу.

## Поиск источников

- Перед сохранением проверяй доступность страницы. При подтверждённой пользователем блокировке исключай конкретный адрес из сохранённых ссылок и браузерного кеша; не считай автоматически заблокированным весь домен. Тайм-аут или сетевой сбой сам по себе не доказывает блокировку.

- Совпадение ёмкости, форм-фактора и SAS/NVMe не делает документ другого производителя или другой модели доказательством характеристики позиции. Явное противоречие производителя/модели в заголовке источника исключает его, даже если поисковые метки positionIds совпадают. Применяй это правило при отборе документов, проверке ответа модели и чтении сохранённого справочника. Разделяй описание самого компонента и документацию платформы/контроллера о его установке; карточка чужого диска не заменяет ни одну из этих проверок.
- Для GPU проверяй точное семейство в заголовке и адресе документа: H100 и H200 — разные модели, и характеристики H100 нельзя переносить на H200 по совпадению интерфейса или охлаждения. Сведения об отдельном SKU подтверждай документом с этим артикулом; страницу серии помечай как источник по модели. Для H200 NVL указывай HBM3e и «до 600 Вт, настраивается» лишь в рамках применимости источника.
- Если в описании позиции не хватает характеристик для решения, самостоятельно ищи их в интернете по точному артикулу и модели; не ограничивайся текстом ведомости. При недоступности источника укажи, какой факт осталось проверить.
- Ищи описание товара по доступным данным: достаточно партномера или названия и описания; не требуй их одновременного наличия. Если партномер не указан, сверяй модель и отличительные характеристики и помечай источник как найденный по описанию, не утверждая совпадение точного SKU.
- Если введён только партномер, определяй производителя по проверенной карточке и используй соответствующий приоритетный домен из настроек; отсутствие названия производителя в строке не отменяет этот приоритет. Не смешивай модели с суффиксом «+» и без него. В предварительном отчёте сохранённые ссылки можно показывать только как справочные, не утверждая, что их документы прочитаны в текущей проверке.
- Для новой позиции без описания или ссылки старайся найти описание по точному артикулу: сначала у производителя, затем в других источниках. В справочник добавляй только проверенные сведения и ссылку с указанием источника; не подменяй близкой моделью. При предварительном отображении списка не запускай автоматический поиск Tavily: его используй после запуска основной проверки пользователем.
- Строй поиск сразу по нескольким признакам: точный партномер, название/модель и distinctive характеристики (интерфейс, форм-фактор, сокет, ёмкость, DDR, поколение PCIe и т. п.). Не ограничивайся запросом по партномеру.
- Карточку и документацию каждой позиции ищи самостоятельно по партномеру, названию и характеристикам. Поиск ссылок для одной платформы не должен зависеть от её установки в другую; вопросы совместной установки рассматривай на следующем этапе анализа. Для компонентов при необходимости дополнительно ищи сведения о размещении в соответствующей платформе.
- Если по точному партномеру нет релевантных результатов, сделай один дополнительный запрос по названию и совокупности характеристик без партномера. Используй его как поиск кандидатов, а не доказательство точной модели.
- Сначала ищи сведения о каждой комплектующей на официальном сайте её производителя: точный артикул, модель, ревизию, спецификацию и документацию. Для условий установки также проверяй документацию производителя конкретной платформы.
- Ресурсы производителя, заданные пользователем в настройках, проверяй первыми для соответствующего производителя. Только если нужной точной позиции или характеристики там нет либо ресурс недоступен, переходи к другим источникам. Не принимай ссылку на похожий товар за точное совпадение.
- Если найдена применимая доступная страница производителя данной позиции, показывай и передавай её первой, независимо от общего порядка других производителей в настройках. Например, для процессора AMD сначала AMD, для контроллера Broadcom сначала Broadcom; дистрибьюторы и продавцы следуют после. Если страница производителя отсутствует или недоступна, явно обозначай альтернативный источник и не выдавай его за производителя.
- Если в описании платформы указана конкретная модель, сначала проверяй документацию именно этой модели. Не делай выводы по документам другой платформы того же производителя без подтверждённой применимости; совпадение бренда и общих характеристик недостаточно. Если в справочнике есть подходящая страница производителя, открой её и передай её содержимое на анализ прежде результатов общего поиска; ссылка по модели не подтверждает партномер поставщика.
- Для видеокарт NVIDIA соблюдай пользовательский порядок ресурсов из настроек и проверяй официальные ресурсы NVIDIA для характеристик конкретной модели. Если NVIDIA не указывает точный партномер, дополнительно сверяй его с каталогом производителя конкретной карты или надёжного поставщика; указывай, какой источник подтверждает модель, а какой — артикул. Не переноси характеристики между настольными и мобильными версиями или разными поколениями.
- Если сайт производителя недоступен, точная модель не найдена или в документации нет нужного факта, используй другие применимые источники: каталоги дистрибьюторов и интеграторов, NIX.ru, технические страницы продавцов и профессиональные обзоры. Указывай источник каждого вывода и не подменяй точную модель похожей.
- Сверяй название, модель, артикул, ревизию и конкретную характеристику внутри текста источника. Результат поиска или совпадение названия сами по себе не подтверждают факт.
- Не сохраняй как источник позиции страницу, которая прямо названа другой моделью, другой ревизией или неприменимой. При наличии похожих партномеров, например разных моделей QLogic, проверяй модель и суффикс; упоминание искомого артикула в сравнении или отказе не является подтверждением.
- Используй первые 1–3 релевантных прочитанных источника на позицию; сохраняй ссылки рядом с подтверждёнными фактами. Не выдумывай цитаты, ссылки или содержимое страниц.

## Вердикты и представление

- В режиме физической совместимости цвет отвечает только за посадку, габариты, крепления и количество мест. BIOS, электрические режимы, частоты, питание и охлаждение перечисляй как замечания, если они не влияют на физическую посадку.
- «Совместимо» ставь, когда подтверждены физический интерфейс/формат, посадка и нужное количество мест.
- «Не совместимо» ставь только при прямом подтверждённом физическом конфликте. Например, M.2 2280 нельзя установить в 2,5-дюймовый отсек напрямую; для красного вердикта также проверь, что точная платформа не имеет подходящих M.2-разъёмов или предусмотренного адаптера.
- Отсутствие упоминания разъёма в краткой карточке не доказывает его отсутствие. Для M.2 ищи точную платформу, считай явно указанные M.2-разъёмы и сравнивай их количество с количеством устройств. Конфликт источников оставляет конкретный аспект неподтверждённым.
- «Не подтверждено» используй только при конкретно недостающем параметре/документе или конфликте источников; укажи, чего именно не хватает. Не понижай все строки из-за отсутствия единого документа на всю сборку, если условия отдельных компонентов закрыты применимыми источниками.
- Показывай отдельную карточку для каждой строки: цветной статус, краткую причину, нужные характеристики позиции с источниками, замечания и рекомендации. Не смешивай замечание с причиной красного статуса.
- Не делай неизвестную версию BIOS причиной физической несовместимости; BIOS — отдельное замечание, если нет явного документированного запрета для точного CPU.
- Дополняй карточки сводкой с однозначным общим вердиктом, затем разбором узлов (платформа/CPU, память, контроллер/накопители, сеть, питание) и практическими замечаниями перед сборкой. Узловая формулировка не должна обещать совместимость, если среди входящих в неё обязательных проверок есть жёлтая или красная.
- В замечаниях по RAID отдельно сверяй число физических отсеков, число прямых портов контроллера, наличие экспандера/бэкплейна и нужные кабели. Число прямых портов не всегда равно пределу поддерживаемых дисков: учитывай заявленное производителем подключение через SAS-экспандер. Не делай вывода о комплектации кабелями или CacheVault/BBU по одной общей модели контроллера: проверь точный SKU и состав коробки.
- Для тракта накопителей используй таблицы руководства с разъёмами бэкплейна и материнской платы: различай число физических коннекторов, линии, поддерживаемый протокол, группы отсеков, назначение кабелей и конфигурацию конкретного SKU. Само наличие разъёма или совпадение названия не доказывает SAS-поддержку или правильную распиновку; требуемые кабели и занятые порты проверяй по схеме. Ссылайся на конкретный документ и не переноси данные на другие ревизии.
- Советы по памяти разделяй на физическое размещение и производительность. Пропускную способность оценивай по документированному числу каналов и фактической схеме установки; число модулей само по себе не доказывает конкретную потерю производительности.
- Номинальная скорость DDR5 RDIMM выше скорости платформы сама по себе не означает несовместимость: стандартная память может работать медленнее по правилам процессора и платформы. Если предусмотрен общий поддерживаемый режим, считай именно разницу скоростей допустимой и укажи ограничение рабочей скорости как замечание. Не подтверждай весь модуль только по снижению скорости: отдельно проверь тип DIMM, ёмкость, организацию чипов, поддержку CPU/BIOS и прочие обязательные условия. Источник общего правила: https://www.kingston.com/en/memory/memory-population-rules.
- DDR5 RDIMM и DDR5 Registered DIMM — два обозначения регистровых модулей памяти DDR5. Считай их совпадением типа, а не несовместимостью. Не отождествляй RDIMM с UDIMM или LRDIMM и проверяй остальные параметры независимо. Источник: https://www.kingston.com/en/memory/gaming/fury-renegade-ddr5-pro-rdimm.
- Все тезисы сводки и замечаний сопровождай применимыми ссылками. Не добавляй ссылки, которые лишь упоминают семейство товара или не подтверждают конкретный тезис.

## Обучение на обратной связи

- При пользовательской поправке отдели предпочтение оформления/процесса от технического утверждения. Технический факт принимай только после проверки источника.
- Исправленный случай обобщай в правило поиска или оценки, применимое к будущим разным сборкам; не превращай один партномер, платформу или ведомость в постоянный каталог совместимости.
- Сохраняй только обобщённые правила и синтетические регрессионные данные. Не записывай в навык реальные BOM, персональные диалоги, API-ключи и отчёты пользователя.
- Если подтверждённое исправление меняет поведение проекта, обнови этот навык и соответствующую логику/синтетическую проверку. Не называй это переобучением весов модели: это курируемая проектная инструкция, которую приложение передаёт выбранной модели.

## Интеграция Provod

- В транспортном JSON допускается замена повторяющихся URL и названий источников на точные `ref` переданных документов. До проверки доказательств и отображения отчёта сервер обязан восстановить полный URL и название во всех проверках, характеристиках, узловых выводах и замечаниях. Неизвестный `ref` не является источником. Область применимости, тип источника, количество проверок и содержательные поля сохраняются. Показывай фактический расход общего модельного запроса один раз, не суммируй его по строкам и не объявляй отсутствие счётчика рассуждений нулевым расходом.
- Снижая стоимость, сохраняй выбранную модель, полный состав сборки, количества, описания, тексты выбранных источников и все обязательные проверки. Убирай только дублирование: состав сборки можно передавать как объединение проверяемых и остальных строк по id. Сохраняй детерминированный порядок документов независимо от времени завершения поиска. Объединяй только идентичные запросы с тем же ключом API; изменение модели, источников, конфигурации или уточнения требует отдельного результата. Не кешируй незавершённые ответы или ошибки и не считай старое списание из кешированного ответа новым расходом.
- Перед анализом проверяй каталог для выбранной модели и используй только параметры, заявленные для неё. Для JSON Schema в проверке сборки используй Chat Completions `response_format`; доступность модели не означает поддержку каждой функции.
- Не повторяй платный запрос автоматически после неполного или неструктурированного ответа. Показывай статус завершения, код/тип ответа и фактическое списание в рублях, если Provod его вернул.

- Не повторяй платный поиск, если прочитанная страница производителя из справочника подтверждает точный артикул или модель и не противоречит позиции. Если документ недоступен или не подтверждает идентичность, продолжай приоритетный и общий поиск; поисковая сниппетная сводка сама по себе не заменяет текст документа. Одинаковые одновременные чтения одной страницы объединяй, а свободные слоты поиска используй без ожидания медленных позиций; количество позиций и индивидуальные выводы при этом сохраняй.
