# ServerCheck

Веб-приложение для предварительной проверки совместимости серверных комплектующих и возможности их совместной установки в корпусе или платформе. Тёмная адаптивная тема, русский интерфейс, без npm-зависимостей и сборки.

## Запуск

Нужен **Node.js 22.9 или новее**.

```sh
npm start
```

Откройте <http://localhost:3000>. Остановка — `Ctrl+C`. Команда `npm install` не требуется. В Windows, если PowerShell блокирует `npm.ps1`, используйте `npm.cmd start`.

Открывать `index.html` двойным щелчком не нужно: JavaScript-модули и API работают через HTTP-сервер.

## Проверка спецификации и первичных документов

1. Введите название сборки и выберите задачу.
2. Вставьте таблицу в поле спецификации: **артикул → описание → количество**, по одной позиции на строку. Можно напрямую скопировать три колонки из Excel. Поддерживаются табуляция, `;`, `|`, несколько пробелов, а также текстовые строки с количеством в конце.
3. Проверьте таблицу распознанных позиций под вводом. Дополнительные характеристики при необходимости задайте в раскрывающихся блоках. Пустые поля остаются неизвестными. Ноль в последней колонке исключает позицию из устанавливаемой сборки.
4. Нажмите «Проверить документы и совместимость». Сначала выполняются отдельный поиск по каждой позиции и чтение найденных документов. Во время работы показывается ход проверки.
5. После завершения всех запросов появятся результаты по строкам, причины и ссылки. Скачиваемый отчёт содержит те же результаты и снимок конфигурации.

### Формат результата по каждой строке

- **Совместимо — зелёным:** основание вывода и ссылки на документы, подтверждающие необходимые условия установки с остальными позициями.
- **Не совместимо — красным:** конкретная причина несовместимости и подтверждающие источники.
- **Не подтверждено — жёлтым:** почему нельзя дать однозначный ответ, какие документы или параметры не подтверждены.

Артикул, описание и количество сохраняются для каждой исходной строки. Повторяющиеся артикулы учитываются отдельными позициями. Цвет дополнен текстом и значком. Результаты выводятся после завершения поиска документов по всем устанавливаемым позициям.

ИИ возвращает структурированные результаты по идентификаторам строк. Пропущенная или дублированная позиция остаётся жёлтой. Зелёный статус требует всех предусмотренных проверок и доказательств по компоненту и платформе либо явной матрицы совместимости. Красный требует подтверждённого отрицательного условия и причины. Используемые ссылки должны присутствовать среди источников выполненного поиска. Документ только на компонент не подтверждает его установку в конкретный сервер. Эти проверки контролируют полноту и наличие источников; семантическая применимость документа к модели и ревизии также должна быть проверена.

Приложение открывается с пустыми полями. Учебной конфигурации и кнопки её загрузки нет. Старый демонстрационный черновик автоматически очищается при обновлении страницы, с сохранением введённого рабочего списка.

Последнее число в строке — **количество изделий**, а не последняя цифра модели или характеристики. Например:

```text
RAM-EXAMPLE    32GB DDR5 DIMM    4
SSD-EXAMPLE    NVMe SSD M.2 2280, 1TB    2
```

Это синтетический пример формата: количество берётся из последней колонки, числа в описании считаются характеристиками.

Каждый SSD/GPU/HBA/NIC сохраняется отдельной строкой. Разные M.2 и U.2 не складываются в одну группу одинаковых накопителей. Пустое количество не заменяется единицей, строки с нулём исключаются из состава, нераспознанные строки явно отмечаются. Для нескольких платформ требуется уточнить распределение компонентов. При наличии спецификации дополнительные поля по умолчанию не участвуют в расчёте. Их можно включить явно. Противоречащие значения исключаются из сравнений и показываются как проблема исходных данных, а не доказанная несовместимость. При изменении списка дополнительные поля отключаются снова.

Регрессионные тесты используют только синтетическую ведомость `test/fixtures/quote.tsv`; пользовательские спецификации в проект не включены.

### Что проверяют правила

- Сокеты, количество CPU, поддерживаемую сокетность и лимит TDP платы.
- Поколение DDR, тип DIMM, число модулей и общий объём RAM.
- Заявленный форм-фактор платы, высоту кулера, его тепловой лимит.
- Длину и профиль плат расширения, занимаемые позиции и число доступных PCIe-слотов.
- Количество отсеков и протокол тракта подключения SATA/SAS/NVMe.
- Предварительный бюджет питания с запасом 25% и учётом отказа одного БП при N+1.
- Необходимость проверить BIOS, поддержку CPU, монтаж, схему заполнения DIMM, райзеры, бэкплейн, кабели, БП/PDB и охлаждение.

Предварительный разбор извлекает явно написанные характеристики и показывает их под полем ввода. При нажатии основной кнопки сервер выполняет проверку первичных документов. Запросы обрабатываются по два одновременно. Источники открываются для чтения через веб-инструмент. Поисковые ссылки допускаются к подтверждению вывода после успешного открытия документа. В карточке сохраняются число поисков, число открытых источников и время проверки.

Дополнительная структурированная форма описывает одну группу одинаковых CPU, DIMM, дисков и карт. Смешанные наборы перечисляйте построчно в спецификации. Первичный режим считает их состав и выявляет доступные по описанию ограничения; для полной проверки точных моделей используйте ИИ и документацию.

## Подключение ИИ-агента

### Provod AI

В локальном `.env` выберите провайдера и заполните ключи.

```dotenv
AI_PROVIDER=provod
PROVOD_API_KEY=YOUR_PROVOD_KEY
PROVOD_MODEL=gemini-3.8-flash
TAVILY_API_KEY=YOUR_TAVILY_KEY
PORT=3000
```

Для диалога Provod AI используется `https://api.provod.ai/v1/responses`, для проверки сборки со структурированным отчётом — `https://api.provod.ai/v1/chat/completions` с `response_format: json_schema`. Точный ID модели выбирается в каталоге текущего рабочего пространства. Кнопка «Проверить ключ и модель» читает `GET /v1/key` и `GET /v1/models`, включая заявленные возможности модели. Если сервис возвращает расходы ключа в RUB, они отображаются в рублях. Сведения о ключе и идентификаторы рабочего пространства остаются на сервере.

В API Provod размещённые инструменты `web_search` и `open_page` недоступны. По каждой позиции параллельно выполняются два коротких запроса Tavily Search: точный артикул и спецификация компонента, затем артикул вместе с платформой и контекстом сборки. Ответы поиска содержат AI-сводки и выдержки максимум из трёх страниц на позицию. Provod анализирует всю сборку одним запросом по JSON Schema. Для запуска проверки оборудования должны быть заполнены оба ключа.

Настройки перечитываются при запросе подключения. Полные ключи вводятся в локальный `.env`, который исключён из Git.

Если запуск из среды агента возвращает `connect EACCES` при обращении к внешнему API, сетевую проверку можно повторить в приложении, запущенном из обычного PowerShell. Для отдельного экземпляра используйте свободный порт.

```powershell
cd C:\projects\my-site
$env:PORT = '3001'
npm.cmd start
```

Откройте <http://127.0.0.1:3001/> и нажмите «Проверить ключ и модель».

Документация провайдеров приведена в [Provod Responses](https://provod.ai/ru/docs/responses), [авторизации Provod](https://provod.ai/ru/docs/authentication), [каталоге моделей](https://provod.ai/ru/docs/catalog) и [Tavily Search](https://docs.tavily.com/documentation/api-reference/endpoint/search).

### Прямое подключение OpenAI

Для прежнего варианта задайте `AI_PROVIDER=openai`, `OPENAI_API_KEY` и `OPENAI_MODEL`. В этом варианте используются встроенные инструменты поиска и чтения OpenAI.

Для анализа Provod сервер использует Chat Completions и JSON Schema `response_format`, чтобы запрос соответствовал параметру, заявленному в каталоге выбранной модели. Предпочтительны документы производителей. При их отсутствии допускаются применимые технические сведения дистрибьюторов, интеграторов, продавцов и профессиональные обзоры. Тип источника отображается рядом со ссылкой. Проверяются точная модель, ревизия, полнота и согласованность характеристик. Неизвестные обязательные параметры требуют статуса «Не подтверждено». Выводы и рекомендации должны иметь применимые ссылки.

Для снижения расходов ответы модели и результаты Tavily Search сохраняются на 24 часа в `.cache/provod/`. Ключи API в кеш не записываются. Повторный полностью совпадающий запрос может использовать сохранённый ответ. На каждую входную позицию выполняются два быстрых параллельных поиска; учитываются до трёх выдержек. Неизвестная версия BIOS показывается как замечание, а не как блокер. Остальные обязательные условия без подтверждения остаются «не подтверждено».

Подключение сервиса проверяется перед запуском. При отсутствии доступа или техническом сбое интерфейс показывает ошибку подключения. Итоговый отчёт формируется после успешного выполнения запросов по всем строкам. Если поиск выполнен, но применимый первичный документ недоступен, позиция получает жёлтый статус с результатом поиска и конкретными недостающими сведениями.

Используется платный OpenAI API. Подготовьте ключ проекта и доступ к модели с поддержкой `web_search`.

1. Скопируйте `.env.example` в `.env`:

   ```powershell
   Copy-Item .env.example .env
   ```

2. Вставьте ключ в **локальный файл `.env`**:

   ```dotenv
   OPENAI_API_KEY=ваш_ключ
   OPENAI_MODEL=gpt-5.4
   PORT=3000
   ```

3. Запустите `npm start` и обновите страницу. Если сервер уже работает, ключ из локального `.env` будет прочитан при следующей проверке подключения.
4. Вставьте список точных моделей, артикулов, количества и ревизий. Нажмите «Проверить документы и совместимость». При желании дополните характеристики вручную.

Если выбранная модель недоступна вашему проекту, задайте другую reasoning-модель Responses API с поддержкой `web_search`, `open_page` и JSON Schema в `OPENAI_MODEL`. Для каждой устанавливаемой позиции выполняется отдельный API-запрос. Весь список передаётся как контекст для проверки совместной установки. Один запрос ограничен четырьмя минутами, общий срок зависит от размера списка и ограничен тридцатью минутами. Ошибки ключа, квоты, сети и незавершённого ответа отображаются в интерфейсе.

Добавьте действующий ключ в локальный `.env` для запуска поиска и чтения документов. Секрет хранится только на сервере. `.env` исключён из Git, `.env.example` содержит пустое поле ключа.

### Данные и границы проверки

- Черновик автоматически хранится в `localStorage` этого браузера. Кнопка «Очистить» очищает его содержимое. Отчёты не сохраняются на сервере.
- Предварительный разбор в поле ввода выполняется в браузере.
- При нажатии основной кнопки в OpenAI отправляются конфигурация, пожелания, распознанные позиции и параметры текущей позиции. Запросы используют `store: false`, с учётом применимой политики обработки данных API.
- Документы и выводы ИИ могут быть неполными. Отсутствие явных конфликтов не означает подтверждённую совместимость. Проверяйте применимость источника к точной ревизии и артикулу.
- TDP — не пиковое потребление. Запас 25% — ориентир, который нужно сверить с калькулятором платформы, GPU-пиками, напряжением сети и лимитами PDB.
- После изменения конфигурации старый отчёт помечается как устаревший. При экспорте сохраняется именно проверенный снимок.
- Сервер слушает только `127.0.0.1`, не имеет авторизации и предназначен для локальной работы. Для внешнего размещения нужны авторизация, HTTPS, лимиты запросов и управление секретами. Публичное развёртывание в этот проект не включено.

Официальные материалы: [Responses API и первый запрос](https://developers.openai.com/api/docs/quickstart), [веб-поиск и цитаты](https://developers.openai.com/api/docs/guides/tools-web-search), [модель GPT-5.4](https://developers.openai.com/api/docs/models/gpt-5.4). Пример модельно-зависимых правил установки памяти: [Intel S2600WF Memory Population](https://www.intel.com/content/www/us/en/support/articles/000055509/server-products/server-boards.html) — эти правила нельзя автоматически переносить на другие платы.

## Проверки проекта

### Переносимый справочник ссылок

Источники, сопоставленные с артикулом или моделью после проверки, сохраняются в `data/component-sources.json`. Этот файл можно включить в коммит и перенести вместе с проектом. При открытии приложения ранее сохранённые ссылки браузера также добавляются в справочник. В записях хранятся партномер, адрес, заголовок, признак совпадения только по модели и дата обновления; полная спецификация и API-ключи не записываются. Совпадение только по модели не подтверждает точный SKU. Ссылки и их применимость могут устаревать, поэтому проверяйте их перед использованием. В GitHub файл попадает только после коммита и отправки изменений.

Приоритетные сайты производителей сохраняются в `data/priority-resources.json` в заданном порядке и могут переноситься с проектом. Если файл ещё не инициализирован, приложение переносит туда список из текущего браузера. После инициализации настройки проекта становятся основными. Тема и черновик остаются в браузере; API-ключи хранятся отдельно в `.env` и не включаются в Git.

```sh
npm test
npm run test:browser
```

Первая команда запускает тесты расчётов и серверного API на встроенном `node:test`. Вызовы OpenAI подменяются тестовыми ответами; деньги не расходуются. Проверяются неизвестные параметры, конфликты RAM, SAS/SATA, размеры карт, N+1, валидация и ошибки API.

Вторая команда использует установленный Chrome или Edge через Chrome DevTools Protocol: проверяет реальную страницу, мобильную ширину, пример, фильтры, устаревший отчёт, сохранение черновика и безопасный вывод. На время проверки запускается собственный локальный сервер. При нестандартной установке браузера укажите `BROWSER_PATH`. Скриншоты и временные профили сохраняются в игнорируемую папку `.tmp/`.

## Структура

```text
index.html                 Интерфейс
styles.css                 Тёмная тема и адаптивная вёрстка
app.js                     Форма, черновик, отчёт, цитаты, экспорт
research.js                Поиск и чтение документов каждой позиции, прогресс
provod.js                  Анализ через Provod, поиск и чтение через Tavily
positions.js               Три статуса, условия и контроль результатов по строкам
report-view.js             Цветные карточки позиций и ссылки на источники
schema.js                  Схема полей и валидация
draft.js                   Очистка старого демонстрационного черновика
engine.js                  Правила совместимости и рекомендации
bom.js                     Разбор строк, количеств, характеристик и итогов
preflight.js               Первичные вопросы к совместной установке
server.js                  HTTP-сервер и интеграция с OpenAI
test/                      Тесты правил и API
test/fixtures/quote.tsv    Синтетический пример формата для регрессионной проверки
docs/compatibility-research-skill.md  Алгоритм поиска, отбора источников и вердиктов
scripts/browser-check.mjs  Проверка в реальном браузере
.env.example               Образец серверных настроек без ключа
.gitignore                 Секреты, временные файлы и локальные артефакты
```
